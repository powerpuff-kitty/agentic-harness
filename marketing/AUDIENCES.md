# Audiences

## Solo developers and AI-heavy builders

Need: consistent context across coding sessions and agents without maintaining a large instruction file manually.

Key outcomes: faster project setup, fewer repeated explanations, reusable procedures, safer upgrades, and clearer project memory.

## Small engineering teams

Need: shared agent behavior and repository conventions that survive individual tools and team members.

Key outcomes: canonical project truth, scoped instructions, reviewable policies, deterministic validation, and repeatable onboarding.

## Agencies and consultancies

Need: reusable project standards across many client repositories while preserving client-specific truth.

Key outcomes: templates, presets, packs, skills, audits, and controlled upgrades.

## Platform and developer-experience teams

Need: standardization and governance across repositories without forcing one application framework or one coding agent.

Key outcomes: composable organizational defaults, auditable repository maturity, quality gates, and vendor-neutral adapters.

## Open-source maintainers

Need: make repositories easier for human contributors and coding agents to understand safely.

Key outcomes: concise instruction routing, durable docs, repeatable maintenance skills, examples, evals, and security boundaries.
