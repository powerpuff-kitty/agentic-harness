# Design system and interaction truth

## Product experience

Describe the intended user experience, interaction principles, information hierarchy, and supported devices.

## Foundations

Reference approved typography, color, spacing, elevation, motion, iconography, breakpoints, and accessibility rules. Prefer semantic tokens over raw values.

## Components

List the canonical component library and its ownership boundary. Product code should consume existing components and tokens rather than create local lookalikes.

## Layouts and patterns

Document accepted shells, navigation, forms, tables, empty/error/loading states, responsive behavior, and recurring flows.

## Content and localization

Define voice, terminology, formatting, localization, and inclusive-language rules.

## Validation

Name design-system compliance, accessibility, visual regression, responsive, and interaction checks expected before release.

Consequential design choices belong in `.agentic/decisions/`; this file describes the current accepted system.
