## Narrative
Describe the overview, audience/problem, solution, own contribution/decisions,
product in use, identity, design system, engineering, outcomes and resources.
Mark each section as ready, omitted with reason, or pending internal authoring.
Do not publish empty placeholders or fabricate evidence to complete the template.

## Composition
Choose the visual purpose first, then a supported layout for each scene. Keep
project-level Design/Design system navigation conditional. Preserve host chrome.
Record the art direction, reading order, image ratios/cropping, captions, mobile
behavior and reduced-motion fallback. No unreviewed free-form style override.

## Assets and publication
Record asset references, dimensions, exact hashes, meaningful alt text, credit,
rights approval and metadata/privacy review. Use synthetic/redacted product data.
Keep inspiration/reference assets separate; font redistribution is not implied.

## Verification
Record exact schema/reference/file checks and the real rendered browser evidence.
Verify narrow screens, zoom, keyboard, image errors, contrast and external requests.
A checklist or schema pass alone is not a release certificate.

## Optional examples
State whether real native specimens or a static gallery already exist. Only propose
web-component distribution for a concrete external consumer. No production writes,
authentication or tracking are required to demonstrate the project.
