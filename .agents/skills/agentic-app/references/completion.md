# Completion and evidence

Read this guide when interpreting completion artifacts or using a supported completion command. It is not necessary for a routine source-only inspection. The target's accepted completion contract remains authoritative; this guide defines no wire format.

## Bind claims to actual work

Record the source and working-tree inputs, relevant rules/configuration, exact permitted check, tool version, exit and scope. Refresh affected checks after input changes; unchanged HEAD is insufficient. Preserve distinct failures, unsupported/not-run checks and missing or truncated output. A passing retry does not erase earlier failures or their resource use.

Check router links, root hygiene, manifest/lock and required module/reference integrity where touched. Run the project's required native tests/quality gates when authorised. A discovered check, planned command or valid report shape is not execution. Report installed structure, project configuration, check configuration and verified behaviour separately.

## Keep the two approvals separate

Approval to execute a command does not approve its result as completion evidence. When the installed trusted CLI supports checks complete, follow the target's canonical contract. Obtain explicit caller review of the exact evidence manifest binding report, producer and reference digests. Do not calculate a digest and submit it as the caller's approval. A model's confidence, previous approval of different bytes or a supplied receipt cannot grant approval.

Respect the verdict's scope and trust mode. Keep producer authentication unverified unless independent evidence establishes it. Missing, stale, mismatched or rejected evidence leaves the affected completion gate unresolved. Acceptance of declared checks/controls is not certification of the entire project, a deployment or a release.

Without a compatible completion tool or required caller approval, return the observed native results and outstanding gates. Do not fabricate a canonical verdict or launch another provider to turn uncertainty into a pass. A bounded analysis may be complete while deployment/release readiness remains unverified.

## Handoff only what is useful

For continuation, retain goal, authorised scope, accepted decisions, source identities, actual changed paths, observed checks, conflicts and the smallest next step. Update an existing task record only when useful and permitted. Do not replay a full transcript or export private evidence. Unknown token usage and unexecuted model trials remain unknown; compact reporting is not evidence of empirical savings.
