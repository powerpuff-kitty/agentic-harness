# Design System Skill

Use for extracting, organizing, generating, or auditing design-system knowledge.

1. Inspect existing design code, tokens, screenshots/Figma references, and accepted examples.
2. Keep observed evidence separate from distilled design rules.
3. Classify findings using `skill/references/design-system-ontology.md`.
4. Normalize raw values into primitive, semantic, and component tokens where justified.
5. Identify reusable foundations, layouts, components, and patterns.
6. Document responsive behavior, interaction states, accessibility, and anti-patterns.
7. Prefer deterministic token/code changes and visual/a11y checks over prose alone.
8. Do not invent a design rule when evidence is ambiguous; record the gap.
