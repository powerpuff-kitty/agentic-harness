# Maturity Levels

## prototype
Optimize for learning and speed. Require product intent, a lightweight architecture map, basic design guidance for UI, and executable tests for critical behavior.

## startup
Add ADRs for consequential decisions, migration discipline, CI, release checks, observability basics, security baseline, and explicit ownership of durable docs.

## production
Require operational runbooks, rollback strategy, structured observability, dependency policy, API/data compatibility, performance budgets, accessibility for user-facing UI, and threat-aware security review.

## critical
Add explicit threat models, auditability, recovery procedures, stricter tool permissions, mandatory review gates, failure/chaos scenarios where relevant, and stronger evidence for security/privacy/compliance claims.

Use maturity to scale rigor. Do not impose critical-system bureaucracy on a prototype.
