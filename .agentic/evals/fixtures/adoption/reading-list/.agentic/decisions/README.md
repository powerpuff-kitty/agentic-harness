# Architecture Decision Records

Use an ADR for a durable, consequential choice with meaningful alternatives or trade-offs. Do not create an ADR for routine implementation detail or temporary task state.

## Naming

`ADR-NNN-short-kebab-title.md`

## Status

`proposed`, `accepted`, `rejected`, `deprecated`, or `superseded`.

## Workflow

1. Copy `ADR-000-template.md` and assign the next number.
2. Describe context and real alternatives.
3. Record the decision, consequences, evidence, and verification.
4. Add the entry to `index.yaml`.
5. Update current truth files when the decision becomes accepted.
6. When superseding an ADR, link both records rather than rewriting history.
