# Agentic Harness Design v0.1 positioning

## Position

**Repository-native design intelligence for AI coding.**

Core promise: analyze an existing product, capture its design language, compile precise implementation context for any AI coding tool, and detect design drift after changes.

## First audience

Developers and small teams already using AI coding tools on existing products who experience:
- inconsistent spacing/colors/geometry across generated changes;
- duplicate or bypassed design-system components;
- repeated manual explanation of visual identity;
- generated pages that look generic rather than project-specific;
- no reliable way to tell whether a new AI-generated screen still follows the product's identity.

## v0.1 loop

1. **Analyze** an existing repository deterministically.
2. **Review** observed and inferred design-system findings.
3. **Preserve** approved identity in a Design Genome.
4. **Compile** task-specific implementation context/prompt without requiring an LLM.
5. **Verify** the resulting changes through re-analysis and design-drift/compliance reporting.

## Product pillars

- Analyze
- Preserve
- Compile
- Verify

Later releases add Create and Research as first-class product pillars.

## Differentiation

Do not lead with "AI design-system generator". That is crowded and does not describe the initial value.

Differentiate through:
- repository-native canonical truth;
- deterministic/offline analysis and prompt compilation where possible;
- model/vendor independence;
- explicit evidence, confidence, provenance, and human approval;
- closed-loop drift detection after generated changes;
- CLI and visual web-app surfaces over compatible canonical artifacts.

## Candidate messaging

- "Make AI code look like your product—not like AI."
- "One design language. Any coding agent."
- "Analyze your design. Preserve it. Compile it for any AI."

Claims must only be published after the corresponding capabilities are implemented and verified.
