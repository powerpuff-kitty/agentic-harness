# Design intelligence research

This directory preserves research and working evidence for Agentic Harness Design. It exists so future contributors and agents can recover the rationale without relying on chat history.

## Status and precedence

Research is evidence, not canonical project truth. Accepted product/design/architecture choices belong in `.agentic/PRODUCT.md`, `.agentic/DESIGN.md`, `.agentic/ARCHITECTURE.md`, and accepted ADRs.

For external claims, record the source, date reviewed, and whether the statement is vendor-documented, independently verified, or inferred. Re-check time-sensitive commercial capabilities and licensing before implementation.

## Files

- [`competitors-and-tools.md`](competitors-and-tools.md) — design-context, extraction, generation, and reference products reviewed.
- [`datasets-and-research-sources.md`](datasets-and-research-sources.md) — open/free UI datasets and current-reference sources.
- [`architecture-conclusions.md`](architecture-conclusions.md) — conclusions that shaped the Design Genome, analyzer, compiler, research-provider model, and artifact interoperability.
- [`v0.1-positioning.md`](v0.1-positioning.md) — first-iteration product slice and market position.

## Core research questions

1. How can a product identity survive agent/model/session changes without becoming a rigid template?
2. Which design facts can be measured deterministically before any AI interpretation?
3. How should imported references remain evidence rather than silently redefining project truth?
4. How can one approved identity compile into prompts, tokens, docs, QA artifacts, and tool context?
5. How can an open research core coexist with optional commercial reference providers without licensing or retention violations?
